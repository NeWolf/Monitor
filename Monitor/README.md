# Monitor — 主线程卡顿监控库

一个轻量的 Android 主线程卡顿监控库，基于 `Looper.setMessageLogging(Printer)` 监控主线程每条消息的分发耗时，并在卡顿发生时**通过后台线程过程采样**定位真正的耗时业务方法。

## 快速使用

```kotlin
val monitor = MainThreadMonitor.Builder()
    .config(MonitorConfig())            // 阈值、采样间隔等
    .listener { blockInfo ->
        Log.w("Monitor", blockInfo.toString())
    }
    .build()

monitor.start()
// ...
monitor.stop()
```

## 监控原理

Looper 在分发每条消息前后会打印标记：

```
>>>>> Dispatching to Handler...   ← 消息开始（记录开始时间 + 启动采样）
   [主线程执行业务代码]
<<<<< Finished to Handler...      ← 消息结束（计算耗时、停止采样、比对阈值）
```

两个标记之间的时间差即为该消息的处理耗时，超过配置阈值即判定为卡顿。

## 为什么用「后台线程过程采样」而不是「超时后单次抓栈」

这是本库的核心设计取舍。

**结论**：只在 `<<<<<`（发现超时）那一刻抓一次主线程栈，**大概率抓不到真正卡住的方法**。

**原因**：

1. **事后现场已清理**：你只有在 `<<<<<` 时才知道本次分发超时，但此刻主线程**已经执行完那段耗时代码**——耗时方法早已返回、出栈。此时抓 `mainThread.stackTrace`，抓到的是主线程"当前"状态（准备处理下一条消息或 Printer 回调自身），不再是刚才卡住的方法。这是典型的"事后诸葛亮"困境：等你确认卡顿时，案发现场已被清理干净。

2. **抓主线程栈必须由别的线程执行**：主线程被业务代码占死（如死循环忙等）时，它自己没有余力去执行"抓栈"动作。只有旁观者线程（本库的 `HandlerThread("MonitorSampler")`）才能在主线程卡住的过程中冷眼旁观、拍下它的栈。

**本库做法**：在 `>>>>>`（消息开始）就启动后台线程持续采样主线程栈（默认每 30ms 一次），`<<<<<` 停止采样。若判定超时，则从这些"过程快照"里挑出**出现次数最多的业务帧**作为元凶方法。

> 类比：想知道嫌疑人案发时段停留在哪，不能等破案后再去问（人早走了），得在案发过程中每隔几秒拍一张监控照片，事后翻照片看他停留最久的地方。

### 方案对比

| 方案 | 能否定位耗时方法 | 原因 |
|------|----------------|------|
| 超时后（`<<<<<`）抓一次 | ❌ 大概率抓不到 | 耗时方法已返回出栈，现场没了 |
| 后台线程过程采样 | ✅ 可以 | 在主线程卡住的过程中持续拍快照，事后聚合 |

### 何时单次抓栈也够用

若耗时来自**单个明确的长方法**、且能在它**还没返回时**抓（如方法内埋点，或 ANR 那种系统级信号），单次抓栈有效。但通用监控无法预知会卡在哪、也无法预先埋点，故只能靠过程采样覆盖。

## 性能优化方向

采样有开销（30ms 一次、抓栈本身有成本），线上可用精度换性能：

- **惰性采样**：耗时超过某个下限后才开始采样。
- **动态调间隔**：卡顿越久，采样间隔可适当调大。
- **采样降频**：采样若干次后自动降频。

## 关键代码位置

| 文件 | 职责 |
|------|------|
| `MainThreadMonitor.kt` | 核心：`printer` 监听分发、`startSampling`/`stopSampling` 后台采样、`findCulpritMethod` 聚合元凶帧、`isBusinessFrame` 过滤系统帧 |
| `MonitorConfig.kt` | 阈值列表、采样间隔（默认 30ms）等配置 |
| `MonitorStatistics.kt` | 消息数、阻塞次数、各阈值命中与耗时方法名的聚合统计 |
| `MainThreadBlockInfo.kt` | 单次卡顿信息（耗时、命中阈值、元凶方法、采样堆栈） |
| `OnMainThreadBlockListener.kt` | 卡顿回调接口 |

> 注意：`isBusinessFrame` 排除监控库自身包 `com.newolf.monitor.` 时，必须保留 `com.newolf.monitor.test`（测试业务类），否则业务帧会被误判为系统帧过滤掉。
